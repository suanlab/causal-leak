# End-to-End Replication Recipe

This document is the replication appendix for the article *Identifier
Leakage and a Device-Rule Class in a Sensor Benchmark: A Forensic Audit of
Water-Leak Classification* (submitted to Data Mining and Knowledge Discovery).
It covers everything needed to reproduce the article's results from a clean
machine.

## Quick path

```bash
pip install -r requirements-lock.txt     # exact environment (Python 3.12.3)
make provenance    # hashes and row checks of the AI Hub release (needs the data)
make cwru          # public CWRU bearing data, ~134 MB, into ../external/cwru
make experiments   # every experiment and figure (scripts/reproduce_all.sh)
make numbers       # print every number the article cites, by section
make verify        # code gate (manuscript checks run only where the source is)
```

`make reproduce` runs them in order, with the five-seed sweep (`make multiseed`)
after the experiments. Without the AI Hub data,
`make numbers` and `make verify` still run: they read only the committed
result files. The same gate runs in CI (`.github/workflows/verify.yml`).

Every result the article reports is printed by `src/cited_numbers.py` with
the section it supports, and `--tables` prints every row of its data tables
(generated by `src/article_tables.py`). Fixed settings are in
`configs/models.yaml`; counts read from the raw release come from
`src/check_provenance.py` and the experiment scripts. The manuscript's own checker, which matches those numbers
against the article's sentences, is kept with the (unreleased) manuscript
source and is available on request.

## Hardware reference profile

The benchmark numbers reported in the paper were measured on:

- CPU: 16-core AMD Ryzen 9 (or equivalent Intel)
- RAM: 64 GB
- GPU: 2 × NVIDIA TITAN Xp (12 GB each), CUDA 12.2 driver 535
- OS: Ubuntu 24.04 LTS

Less GPU memory is fine; deep experiments fit comfortably in 6 GB.
For the tree experiments only, a 16-core CPU machine without any
GPU suffices.

## Software environment

Two equivalent ways:

### Conda / venv

```bash
# Python 3.12 is required (PyTorch 2.5.1 cu121 wheels)
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt   # exact versions used for the article
```

### Docker

```bash
docker build -t causal-leak:dmkd .                      # Python 3.12.3 + requirements-lock.txt
docker run --rm causal-leak:dmkd make verify numbers PAPER_DIR=__none__
docker run --rm --gpus all \
  -v /path/to/kcc-water/Dataset:/data -e CAUSAL_LEAK_DATA_DIR=/data \
  -v "$(pwd)/results":/work/causal-leak/results \
  causal-leak:dmkd make reproduce
```

## Dataset

The AI Hub water-leak vibration dataset (dataset ID 138) is distributed by the
National Information Society Agency of Korea through AI Hub; at the time of
writing the portal accepts applications from users in Korea only. Download the
Training and Validation archives and place them, with their extracted class
CSVs, under

    ../kcc-water/Dataset/Training/   (archive + in/out/noise/other/normal-training.csv)
    ../kcc-water/Dataset/Validation/ (archive + ...-validation.csv)

The analyses read two derived files in `../kcc-water/Dataset/`,
`train_with_site_name_4.csv` and `val_with_site_name_4.csv`, which add an
address to each site code. `src/check_provenance.py` fixes their lineage:
SHA-256 of the archives, the extracted CSVs and the derived files; each
extracted CSV byte-identical to an archive member; every derived row matched
to exactly one distributed row on (site, sid, ldate) with all 536 distributed
columns equal; and the four administrative codes equal to the digits of the
site code. Its output, `results/provenance_results.json`, is committed, so the
hashes can be compared against a fresh download. Override the location with
`CAUSAL_LEAK_DATA_DIR`.

The public CWRU bearing data for the planted-shortcut experiment are fetched
by `scripts/fetch_cwru.sh` (40 files; set `CWRU_DIR` to relocate).

## Reproducing every figure and table

`make reproduce` (or `scripts/reproduce_all.sh` followed by `make multiseed`)
runs every experiment in dependency order. The steps behind the article are:

| Article | Script(s) | Result file(s) |
|---|---|---|
| Data lineage (Sec. 4.6) | `src/check_provenance.py` | `provenance_results.json` |
| Identifier lookup, A1 (Sec. 5.1) | `src/run_identifier_audit.py`, `src/run_audit_inference.py lift` | `identifier_audit_results.json`, `audit_inference_results.json` |
| Device rule, T1–T3 (Sec. 5.2) | `src/run_device_rule.py`, `src/run_audit_inference.py sufficiency` | `device_rule_results.json` |
| Evaluation ladder (Table 5, Fig. 2) | `src/run_matrix.py`, `src/run_sensor_holdout.py`, `src/run_loro.py`, `src/summarize_leak_f1.py` | `matrix_results.json`, `sensor_holdout_results.json`, `loro_results.json`, `leak_f1_results.json` |
| Region-level inference (Sec. 5.4) | `src/run_audit_inference.py region_level` | `audit_inference_results.json` |
| County and temporal holdouts | `src/run_sigungu_ood.py`, `src/run_temporal_split.py` | `sigungu_ood_results.json`, `temporal_split_results.json` |
| Model families (Appendix B) | `src/run_extra_baselines*.py`, `src/run_irm_*.py`, `src/run_domain_alignment.py` (+ `CAUSAL_VAL_MODE=region`), `make multiseed` | `extra_baselines_multiseed.json`, `irm_*_results*.json`, `domain_alignment_results*.json`, `multiseed_summary.json` |
| Triage simulation, A4 (Sec. 5.6, App. A) | `DISPATCH_FEATURES=all src/run_dispatch_operating_points.py <region>`, `DISPATCH_FEATURES=all src/analyze_dispatch.py` (nested-band sensitivity without the variable) | `dispatch_op_all/`, `dispatch_operating_points_all_results.json` |
| Planted shortcuts (Sec. 3.3) | `scripts/fetch_cwru.sh`, `src/run_audit_semisynthetic.py` | `audit_semisynthetic_results.json` |

Each script writes its results to `results/<name>_results.json` together
with a `.log` file capturing console output. `configs/models.yaml` gives every
model's configuration with the command that trains it.

## Figure regeneration

```bash
FIG_TERM=alarm python src/make_figB1_ladder.py      # Fig. 2 (evaluation ladder)
FIG_TERM=alarm python src/make_figB3_models.py      # Fig. B2 (model families)
FIG_DISPATCH=all python src/make_figB2_dispatch.py  # Fig. A1 (triage trade-off)
python src/make_figB5_operating.py                  # Fig. 1 (operating characteristics)
```

All output is in `results/figs/*.pdf` (vector format). `make figures` also
regenerates the figures of the earlier analyses kept in this repository.

## Troubleshooting

- `python: command not found` from `run_multiseed.sh`: set the
  `PYBIN` environment variable to your interpreter, e.g.
  `PYBIN=/path/to/.venv/bin/python bash src/run_multiseed.sh`.
- CUDA OOM on TITAN Xp: reduce the batch size in `RunConfig` to 264.
- LightGBM hangs under high CPU contention: reduce `n_jobs` to 4
  (already done in `run_extra_baselines.py`).
- Mismatched seed-42 results vs paper: ensure `data.py` was not
  modified; the data partition seed is fixed at 42 in
  `irm_core.py:SPLIT_SEED`.
